## 1. 成品层状 NCA（R-3m，No.166，Hall `-R 3 2"`）

### 1.1 骨架来源 COD 1520789（Arai et al., J. Power Sources 90 (2000) 76）

该条目是**真实测定**的层状锂过渡金属氧化物，实测化学式
`Co0.1 Li1.03 Mn0.1 Ni0.77 O2` —— 注意它本身是 **NCM811**，不是 NCA。
它的价值在**骨架**：R-3m 六方设置、36 条对称操作、O 在 6c（z=0.259）、
Li 层与 TM 层的反位分布都是实测值。NCA 四档配比全部由它派生（§2）。

原子占位（原文逐行、逐列核验）：

| label | 元素 | x | y | z | occ | 所属层 |
|---|---|---|---|---|---|---|
| `Li1` | Li | 0 | 0 | **0.5** | 0.98 | **Li 层** |
| `Ni1` | Ni | 0 | 0 | **0.5** | 0.02 | **Li 层**（混排） |
| `Ni2` | Ni | 0 | 0 | **0** | 0.75 | **TM 层** |
| `Co1` | Co | 0 | 0 | **0** | 0.10 | **TM 层** |
| `Mn1` | Mn | 0 | 0 | **0** | 0.10 | **TM 层** |
| `Li2` | Li | 0 | 0 | **0** | 0.05 | **TM 层**（额外 Li） |
| `O1` | O | 0 | 0 | 0.259 | 1.00 | 6c |

**读法**：Li 层（z=0.5）= Li0.98 + Ni0.02 → **2% Li/Ni 混排**；TM 层（z=0）=
Ni0.75 + Co0.10 + Mn0.10 + Li0.05。总 Li = 1.03，总 Ni = 0.77。

> ⚠ **位点命名陷阱（务必注意）**：按 International Tables 的 R-3m 标准取法，
> **3a 是 (0,0,0)、3b 是 (0,0,1/2)**。本 CIF 把 **Li 层放在 z=0.5、TM 层放在 z=0**，
> 相当于取了另一套原点，因此**不能**按 z 值直接叫作「3a = Li 层」。
>
> **代码约定（T3.1）**：识别 Li 层/TM 层一律**按占位内容判定**
> （Li 占位最高的那个 3 重位 = Li 层），**不看 z 坐标、不硬编码 3a/3b**。
> 报告里同时给出「实测 z 坐标」与「Wyckoff 多重度」两个客观量。

## 2. NCA 四档配比 —— COD 无实测层状 NCA CIF（已查证）

**查证结论**：COD 的 `inorg_manifest` 里没有 Ni-Co-Al 层状氧化物条目；
`Al` 与层状 NCA 的组合零命中。因此只能派生。

**派生规则**（`tools/build_cif_pack.py::DERIVE_LIST`）：

1. 骨架、对称操作、O 的 z 坐标全部继承 COD 1520789（**不动**）；
2. **Li 层**保持 `Li 0.98 + Ni 0.02`（2% 反位，实测值）；
3. **TM 层**改为 `Ni (x−0.02) / Co y / Al 0.05 / Li 0.02` —— 两个 0.02 是**配平项**：
   - TM 位补 `Li 0.02`，使 3b 位占位之和 = 1.00；
   - 于是总 Li = 0.98 + 0.02 = **1.00**，总 Ni = 目标值（0.80 / 0.82 / 0.85 / 0.90）。
4. 只改 `_chemical_formula_sum`、TM 位元素与占位；其余保持模板原值。

**为什么必须这样配平**：`refine/qpa.infer_z()` 用「原子占位 ÷ 配方」反算 Z，
再用 Z·M·V 做 Hill–Howard 定量。总 Li 若不是 1.00，`_chemical_formula_sum`
写成 `Li1 Ni0.8 …` 就与占位对不上，反算会抛 `ValueError`（这是**设计如此**：
手填配方被拒绝，比悄悄算错 Z 好）。

| 文件 | TM 层占位 | 总 Ni | 公式 |
|---|---|---|---|
| `NCA_80_15_05.cif` | Ni 0.78 / Co 0.15 / Al 0.05 / Li 0.02 | 0.80 | `Al0.05 Co0.15 Li1 Ni0.8 O2` |
| `NCA_82_13_05.cif` | Ni 0.80 / Co 0.13 / Al 0.05 / Li 0.02 | 0.82 | `Al0.05 Co0.13 Li1 Ni0.82 O2` |
| `NCA_85_10_05.cif` | Ni 0.83 / Co 0.10 / Al 0.05 / Li 0.02 | 0.85 | `Al0.05 Co0.1 Li1 Ni0.85 O2` |
| `NCA_90_05_05.cif` | Ni 0.88 / Co 0.05 / Al 0.05 / Li 0.02 | 0.90 | `Al0.05 Co0.05 Li1 Ni0.9 O2` |

> **晶胞四档完全相同（2.8645 / 14.1610）是有意为之**：NCA 各配比的真实晶胞差
> 在 0.01 Å 量级、峰强差 0.03–0.14 %（`test_real_models.py` 实测），XRD 分不开。
> 给每档单独编一个晶胞等于制造"看起来能区分型号"的假象。
> 型号必须由 ICP/EDS 定 —— 见 `docs/STD_FREEZE.md` §1 边界声明。

**查证结论**：COD 中**没有** Ni-Co-Al 氢氧化物或碳酸盐的实测结构
（`Ni+Co+Al+H+O` 与 `Ni+Co+Al+C+O3` 元素组合均无命中），故前驱体统一用

**实测价值**：池内有了 `precursor_NCA_OH` 之后，真实三元氢氧化物前驱体
（`XRData/csuHJW/Data043：Ni(OH)2`，P-3m1、a=3.130435 / c=4.619966）在判定门
被正确分流为 `precursor_hydroxide` —— NCM 版这份实样被判成 `other`。这是
NCA 版比 NCM 版**更好**的一处，原因只是候选池里补了同骨架条目。

## 4. 规范化说明（重要）

COD 原始 CIF 有两种书写习惯会让家族解析器失效：

| 现象 | 例子 | 家族解析器行为 |
|---|---|---|
| 数值带 esd 括号 | `_cell_length_a 3.1268(1)` | `float()` 失败 → **晶胞退化为 1.0** |
| 原子坐标带 esd | `O1 ... 0.2153(4)` | `_to_float` 返回 None → **该原子被静默丢弃** |
| 原子 loop 多余列 | `symmetry_multiplicity` / `Wyckoff_symbol` / `attached_hydrogens` | 列数不符时可能整行跳过 |

实测：`precursor_NiOH2.cif` 原样送入解析器只得到 **1 个原子**（应为 5 个），
`|F|²` 全错且**不报错**——这是最危险的一类缺陷。

**内置 CIF 的处理**：`tools/build_cif_pack.py` 写入时调用 `normalize_cif_text()`，
只改书写形式、**不动任何数值**：
1. 去掉晶胞/原子数值的 esd 括号（`3.1268(1)` → `3.1268`）；
2. 原子 loop 重排为 7 列标准集（label / type_symbol / fract_x / fract_y /
   fract_z / occupancy / U_iso_or_equiv），丢弃解析器不读的列。

`INDEX.json` 同时记录 **规范化后 sha256** 与 **COD 原始文件 sha256**（`cod_sha256`），
可逐份回溯到原始字节。

**展开数自洽校验**（`tools/verify_cif.py`）：按对称操作把原子展开到惯用胞，
核对原子数 —— NCA_80_15_05=24、LiAlO₂=16、三水铝石=56、NiO=8。这一步能抓住
"loop 丢列导致原子少了"这类静默错误。

**用户导入 CIF 的同类问题**：由 **T1.2b（CIF 解析器健壮性加固）** 在解析器层
解决，不依赖用户手上的文件是否规范化。
